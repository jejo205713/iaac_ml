# Data sources & attribution

The training data is a single file, **`dataset.jsonl`** (44,407 rows;
`split` ∈ {train, val, test}). Every row carries a **`source`** field recording
its provenance. The raw upstream corpora were removed from this repo to keep it
lean — but the *derived* command rows remain, so their licenses still apply.

> ⚠️ **Read before publishing or shipping commercially.** Several sources below
> carry **attribution (CC-BY)**, **share-alike**, or possibly **non-commercial**
> terms. Attribution sources *require* credit; non-commercial/share-alike terms
> can constrain a commercial product. **Verify each upstream license** for your
> use case — the labels below are best-effort, not legal advice.

## Labeling policy (safety-biased)

**When in doubt, flag — never allow.** A command only earns a `BENIGN` or `ADMIN`
label if it is *certainly* safe. Any command with genuine uncertainty or dual-use
capability (remote data transfer like `scp user@host:`, destructive verbs like
`docker rm` / `rm -rf`, security-control disable like `systemctl stop auditd`) is
labeled with its attack class so the model learns to flag it — downstream that
yields block/review, not silent allow. We accept the occasional false flag (extra
review) to avoid a false allow (a missed attack). This mirrors the runtime
guardrail's own bias ("prefer false-PROTECTED over false-None"). Known-safe ops
(`chmod 644 nginx.conf`, `git status`, `kubectl get`) stay BENIGN/ADMIN — the
policy is about *uncertainty*, not about touching sensitive paths.

## Sources present in `dataset.jsonl` (by `source` field)

### Original to this project (no third-party license)
| `source` | What |
|---|---|
| `expert` | Expert-authored synthetic command strings |
| `generated` | Generated by this repo's `gen_*.py` generators |
| `docs`, `sector-guide` | Hand-written examples |
| `redteam_pentest_2026_07_03` | 631 commands from an authorized red-team pentest of the live IAAC classifier (evasion/obfuscation/chaining/catastrophic + benign controls). Labels are **rule-engine-derived** (each row tagged by the matched rule's `intent`) with manual adjudication of the residual — NOT the original keyword heuristic, which mislabeled ~200 attacks. Train-split only. Raw seed: `redteam_pentest_2026_07_03.jsonl`. |
| `generated_benign_v3` | 523 diverse, realistic BENIGN/ADMIN commands (dev/file/git/cloud/IaC/DB-read/observability ops) generated by `gen_benign_admin_v3.py` to offset the attack-heavy pentest data and lower false-positive risk on legit work. Every row validated against the live classifier (any that BLOCK were dropped). Raw seed: `generated_benign_admin_v3.jsonl`. |

## Not in this repo
- **Raw upstream corpora** (`datasets/`) — removed; re-clone from the projects above.
- **Trained weights** (`*.onnx`, `*.safetensors`) — rebuild via `run_all.sh` / `train_transformer.py`.
- **`_quarantine_realdata_unsafe.jsonl`** — quarantined real data, intentionally not published.

Command **strings only** — nothing in this repo executes.
